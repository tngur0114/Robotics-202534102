## 1. 로봇의 정의와 기원

### 1-1. 로봇의 기원

- Robot이라는 용어는 체코 작가 카렐 차페크의 1920년 희곡 Rossum's Universal Robots(R.U.R.)에서 등장했다.
- 체코어로 강제 노동을 뜻하는 *robota*에서 유래했으며, 인간의 노동을 대신 수행하는 존재를 의미했다.

### 1-2. 로봇의 정의

로봇은 주어진 작업을 자동으로 수행하도록 설계된 기계 시스템이다. 일반적으로 센서, 제어 장치, 구동 장치로 구성되며 사람이 모든 동작을 직접 조작하지 않아도 작업을 수행할 수 있다.

자동화 기능이 있다고 해서 모든 기계를 로봇으로 분류하는 것은 아니다. 강의에서는 세탁기에 로봇 팔을 추가해 세탁물을 꺼내 건조기로 옮기는 예시를 통해 일반 가전제품과 로봇의 차이를 설명했다.

## 2. 로봇 소프트웨어 구조

로봇의 기본적인 동작 과정은 Perception, Planning, Control의 세 단계로 구분할 수 있다.

```text
Perception → Planning → Control
     ↑                     │
     └───── Feedback ──────┘
```

### 2-1. Perception(인지)

- 센서를 통해 주변 환경과 로봇 자신의 상태를 파악하는 과정
- 카메라, LiDAR 등을 이용한 장애물 및 주변 환경 인식
- 로봇의 현재 위치, 배터리 상태, 모터 상태 확인

### 2-2. Planning(계획)

- 인지 결과를 바탕으로 목표를 달성하기 위한 경로나 행동을 결정하는 과정
- 목적지까지의 이동 경로 생성
- 이동 거리, 장애물, 충돌 가능성, 이동 시간 등을 고려

### 2-3. Control(제어)

- 계획된 경로나 행동을 실제 움직임으로 실행하는 과정
- 모터와 액추에이터에 제어 명령 전달
- 목표한 움직임과 실제 움직임 사이의 오차 확인 및 보정

로봇이 이동하는 동안 주변 환경과 자신의 위치는 계속 변한다. 따라서 제어 결과를 다시 인지하고 필요한 경우 계획을 수정하는 폐루프(Closed-loop) 구조를 사용한다.

실제 로봇에 알고리즘을 바로 적용하면 충돌이나 파손이 발생할 수 있으므로 시뮬레이션 환경에서 먼저 검증하기도 한다.

## 3. 지능형 로봇과 딥러닝

### 3-1. Rule-based Control과 Adaptive Behavior

- **Rule-based Control**: 상황별 동작을 미리 정의하는 방식. 정해진 환경에서는 효과적이지만 예상하지 못한 상황에 대응하기 어렵다.
- **Adaptive Behavior**: 환경 변화와 입력에 따라 행동을 조정하는 방식

실제 환경에서는 발생할 수 있는 모든 상황을 규칙으로 정의하기 어렵다. 딥러닝을 활용하면 데이터로부터 특징과 행동을 학습하여 새로운 상황에 대응할 수 있다.

### 3-2. LLM, VLM, VLA

| 구분 | 의미 | 주요 기능 |
|---|---|---|
| LLM | Large Language Model | 언어 이해 및 생성 |
| VLM | Vision-Language Model | 시각 정보와 언어 처리 |
| VLA | Vision-Language-Action | 시각·언어 정보를 바탕으로 행동 생성 |

VLA는 시각 정보와 언어 명령을 처리하는 것에서 나아가 실제 로봇의 행동까지 생성한다.

텍스트, 이미지, 오디오 등 서로 다른 형태의 데이터를 함께 처리하거나 학습하는 방식을 Multimodal 학습이라고 한다.

### 3-3. Embodied AI와 Physical AI

- **Embodied AI**: 물리적 또는 가상적인 몸을 가진 에이전트가 환경과 상호작용하며 행동하는 분야
- **Physical AI**: 실제 물리적 환경에서 인지, 판단, 행동을 수행하는 기술

로봇이 실제 환경에서 작업하기 위해서는 소프트웨어의 판단 능력뿐 아니라 센서와 구동 장치를 통한 물리적 상호작용도 필요하다.

## 4. 로보틱스의 응용 분야

### 4-1. SLAM과 3D Mapping

**SLAM(Simultaneous Localization and Mapping)** 은 로봇이 자신의 위치를 추정하면서 동시에 주변 환경의 지도를 생성하는 기술이다.

- LiDAR, 카메라 등의 센서 데이터 활용
- 로봇의 위치 추정 및 2D/3D 지도 생성
- 자율주행, 내비게이션, 자율 탐사 등에 활용
- 신경망을 이용해 공간 정보를 표현하는 Neural Map 방식도 존재

### 4-2. Computer Graphics와 Computer Vision

| 구분 | 주요 역할 |
|---|---|
| Computer Graphics | 3D 모델을 2D 이미지로 표현 |
| Computer Vision | 이미지로부터 물체, 위치, 공간 구조 등을 추정 |

Graphics에서 3D 정보를 2D 이미지로 변환한다면, Vision에서는 반대로 2D 이미지로부터 3D 구조를 추정하기도 한다.

두 분야 모두 카메라 모델, 좌표 변환, 투영 등의 원리를 활용하며 3D Reconstruction, Digital Twin, AR 등에 적용된다.

### 4-3. 점검 로봇과 AR Navigation

- 점검 로봇은 사람이 접근하기 어려운 공간에서 환경을 인지하고 이상 상태를 확인한다.
- 이동 중 장애물을 감지하고 정상 상태와 현재 상태를 비교한다.
- AR Navigation은 카메라 영상과 위치 추정 기술을 이용해 실제 화면 위에 이동 방향이나 경로를 표시한다.

## 5. High-level과 Low-level

로봇 시스템에서는 복잡한 연산을 수행하는 부분과 하드웨어를 직접 제어하는 부분을 구분할 수 있다.

### 5-1. High-level

- 주변 환경 인지, 위치 추정, 경로 계획, 의사결정 담당
- SLAM, 이미지 처리 등 연산량이 많은 작업 수행
- PC, SBC, 서버 등을 사용
- Linux와 ROS 2 기반의 개발 환경 활용

### 5-2. Low-level

- 모터, 서보, 센서 등 하드웨어 직접 제어
- High-level에서 전달받은 명령 실행
- 센서 데이터 수집 및 처리
- MCU와 펌웨어를 사용하며 주로 C/C++로 개발

### 5-3. 제어 주기(Control Period)

제어 주기는 제어 알고리즘이 반복적으로 실행되는 시간 간격이다.

일반적인 OS에서는 스케줄링에 따라 작업 실행 시간이 달라질 수 있다. 하지만 모터 제어와 같은 Low-level 작업에서 제어 주기가 불규칙하면 움직임에 오차가 발생할 수 있으므로 일정한 주기를 유지하는 것이 중요하다.

실시간 제어가 필요한 경우 RTOS(Real-Time Operating System)를 사용해 작업의 실행 시간을 관리하기도 한다.

| 구분 | High-level | Low-level |
|---|---|---|
| 역할 | 인지, 계획, 판단 | 하드웨어 제어 |
| 주요 작업 | SLAM, 경로 계획 | 모터 제어, 센서 입력 |
| 사용 장치 | PC, SBC, 서버 | MCU |
| 개발 환경 | Linux, ROS 2 | Firmware, RTOS |
| 중요 요소 | 연산 성능 | 제어 주기 및 응답 시간 |

## 6. SBC와 MCU

### 6-1. SBC(Single Board Computer)

프로세서, 메모리, 입출력 인터페이스 등 컴퓨터의 주요 기능을 하나의 회로 기판에 구성한 장치이다.

- Linux와 같은 운영체제 실행 가능
- 복잡한 데이터 처리 및 연산에 적합
- 대표적인 장치: Raspberry Pi, NVIDIA Jetson

### 6-2. MCU(Microcontroller Unit)

CPU, 메모리, 주변 장치 제어 기능 등을 하나의 칩에 통합한 장치이다.

- SBC에 비해 제한된 연산 및 메모리 자원
- GPIO, ADC, PWM을 이용한 하드웨어 제어
- 센서, 모터, LED, 버튼 등의 입출력 처리
- 대표적인 장치: ESP32, AVR 계열 MCU

로봇에서는 SBC가 경로 계획과 같은 High-level 작업을 수행하고, MCU가 전달받은 명령에 따라 모터를 제어하는 구조를 사용할 수 있다.

## 7. Linux와 터미널 기초

### 7-1. Linux

- 오픈소스 기반의 운영체제 환경
- 다양한 개발 도구 및 패키지 사용 가능
- 터미널을 통한 시스템 설정과 자동화
- ROS 2 개발 환경으로 Ubuntu가 널리 사용됨

### 7-2. CLI(Command Line Interface)

터미널에 명령어를 입력하여 시스템을 조작하는 방식이다.

| 명령어 | 기능 |
|---|---|
| `pwd` | 현재 경로 확인 |
| `cd` | 디렉토리 이동 |
| `ls` | 파일 및 디렉토리 목록 확인 |
| `ls -a` | 숨김 파일을 포함한 목록 확인 |
| `mkdir` | 디렉토리 생성 |
| `touch` | 파일 생성 또는 수정 시간 갱신 |
| `cp` | 파일 및 디렉토리 복사 |
| `mv` | 파일 이동 또는 이름 변경 |
| `rm` | 파일 삭제 |
| `ping` | 네트워크 연결 상태 확인 |
| `echo` | 문자열 출력 |
| `chmod +x` | 실행 권한 추가 |
| `sudo` | 관리자 권한으로 명령 실행 |

Tab 키를 사용하면 파일명이나 명령어를 자동완성할 수 있다.

### 7-3. 패키지 관리

APT(Advanced Package Tool)는 Ubuntu 등 Debian 기반 Linux에서 사용하는 패키지 관리 도구이다.

```bash
sudo apt update
sudo apt upgrade
```

- `apt update`: 패키지 목록 갱신
- `apt upgrade`: 설치된 패키지 업데이트

## 8. 로봇 개발 환경

### 8-1. 작업 공간(Workspace)

ROS 2는 센서 처리, 위치 추정, 경로 계획, 제어 등 로봇을 구성하는 여러 기능 사이의 데이터 교환을 지원한다.

ROS 2 패키지는 일반적으로 `colcon`을 사용해 빌드하며, 펌웨어와 테스트 코드는 별도의 디렉토리로 구분하여 관리한다.

| 디렉토리 | 용도 |
|---|---|
| `colcon_ws` | ROS 2 패키지 개발 및 빌드 |
| `firmware` | MCU 펌웨어 코드 |
| `scratch` | 테스트 및 임시 코드 |

### 8-2. 개발 도구

- **VS Code**: 코드 작성 및 편집
- **Git**: 소스 코드의 변경 이력 관리
- **GitHub**: 원격 리포지토리 관리 및 협업
- **CMake**: 프로젝트 빌드 과정 구성

## 9. 임베디드 시스템 기초

### 9-1. Embedded System

특정 기능을 수행하도록 설계된 컴퓨터 시스템으로, 일반적으로 더 큰 장치나 기계 내부에 포함된다.

자동차의 방향지시등이나 후진 경고 장치 등이 대표적인 예시이며, 로봇에서는 센서 데이터 처리와 모터 제어 등에 활용된다.

### 9-2. 전압, 전류, 저항

| 구분 | 의미 | 단위 |
|---|---|---|
| 전압(Voltage) | 두 지점 사이의 전위차 | V |
| 전류(Current) | 단위 시간당 흐르는 전하량 | A |
| 저항(Resistance) | 전류의 흐름을 제한하는 성질 | Ω |

전압, 전류, 저항 사이의 관계는 옴의 법칙(Ohm's Law)으로 나타낼 수 있다.

**V = IR** 

### 9-3. GND(Ground)

- 회로에서 전압을 측정하는 기준 전위로, 일반적으로 0V를 기준으로 사용한다.
- 서로 연결된 MCU, 센서, 액추에이터가 동일한 전압 기준을 사용하도록 공통 GND(Common Ground)를 구성한다.

### 9-4. GPIO(General Purpose Input/Output)

입력 또는 출력으로 설정할 수 있는 범용 입출력 핀이다.

- Input: 버튼이나 센서의 신호 입력
- Output: LED, 모터 제어 회로 등에 신호 출력

### 9-5. Digital과 Analog

| 구분 | Digital | Analog |
|---|---|---|
| 신호 | 이산적인 값 | 연속적인 값 |
| 표현 | HIGH, LOW | 일정 범위의 전압 |
| 예시 | 버튼 입력, LED 출력 | 가변저항, 아날로그 센서 |

ESP32의 GPIO는 일반적으로 3.3V 로직을 사용한다.

### 9-6. ADC(Analog-to-Digital Converter)

연속적인 아날로그 전압을 MCU에서 처리할 수 있는 디지털 값으로 변환하는 장치이다.

ADC의 해상도가 n비트일 때 표현할 수 있는 값의 개수는 다음과 같다.

**N = 2^n**

따라서 디지털 값의 범위는 다음과 같다.

**0 \sim (2^n - 1)**

| 해상도 | 디지털 값 범위 |
|---|---|
| 8 bit | 0 ~ 255 |
| 10 bit | 0 ~ 1023 |
| 12 bit | 0 ~ 4095 |

해상도가 높을수록 같은 입력 범위의 전압을 더 세밀하게 구분할 수 있다.

ESP32에서는 ADC를 이용해 가변저항이나 센서의 아날로그 전압을 읽을 수 있다. 다음 실습에서는 GPIO와 ADC를 사용해 LED, 버튼, 가변저항을 직접 제어한다.
