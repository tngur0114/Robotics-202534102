# [1주차] 로보틱스 인지·계획·제어 파이프라인과 임베디드 기초

## 학습 내용

로봇의 기본 구조와 동작 원리를 이해하기 위해 **인지(Perception) → 계획(Planning) → 제어(Control)** 파이프라인을 학습했다. 이후 딥러닝 기반 지능형 로봇과 Physical AI의 개념을 살펴보고, 실제 로봇 시스템에서 고수준 판단과 저수준 제어가 어떻게 구분되는지 알아보았다.

또한 로봇 개발에 필요한 Linux 환경과 기본 명령어를 익히고, MCU 및 임베디드 시스템의 기초 개념을 학습했다.


## 핵심 개념 정리

### 1. 로봇의 정의와 기원

**[1-1] 로봇의 기원**

- **Robot**이라는 용어는 체코 작가 카렐 차페크의 1920년 희곡 Rossum's Universal Robots(R.U.R.)에서 등장했다.
- 체코어로 강제 노동을 뜻하는 *robota*에서 유래했으며, 초기에는 인간의 노동을 대신 수행하는 존재를 의미했다.
- 현재 로봇 역시 사람이 수행하기 어렵거나 반복적인 작업을 대신한다는 점에서 초기 개념과 연결된다.

**[1-2] 로봇의 정의와 자동성**

- **로봇(Robot)**: 주어진 작업을 자동으로 수행하도록 설계된 기계 시스템이다.
- 로봇의 중요한 특징 중 하나는 **자동성(Automation)** 으로, 사람이 모든 동작을 직접 조작하지 않아도 작업을 수행할 수 있어야 한다.
- 자동화 기능을 가진 모든 기계가 로봇으로 분류되는 것은 아니며, 로봇은 일반적으로 센서, 제어 장치, 구동 장치 등을 통해 물리적인 작업을 수행한다.
- 예를 들어 세탁기에 로봇 팔을 추가해 세탁물을 꺼내 건조기로 옮기도록 만들면, 단순한 가전제품에서 로봇 시스템으로 기능이 확장된다.

### 2. 로봇 소프트웨어 구조

로봇의 기본적인 동작 과정은 **인지(Perception) → 계획(Planning) → 제어(Control)** 로 구분할 수 있다.

**[2-1] 인지(Perception)**

- 센서를 통해 주변 환경과 로봇 자신의 상태를 파악하는 과정이다.
- 카메라, LiDAR 등의 센서를 이용해 장애물, 사람, 주변 공간에 대한 정보를 얻는다.
- 외부 환경뿐 아니라 배터리, 모터 상태, 현재 위치 등 로봇 내부 상태도 인지에 포함된다.

**[2-2] 계획(Planning)**

- 인지한 정보를 바탕으로 목표를 달성하기 위한 경로나 행동을 결정하는 과정이다.
- 로봇이 목적지까지 이동할 때 장애물과 주변 환경을 고려해 이동 경로를 생성하는 것이 대표적인 예시이다.
- 경로를 계획할 때는 이동 거리뿐 아니라 안전성, 충돌 가능성, 이동 시간 등을 고려할 수 있다.

**[2-3] 제어(Control)**

- 계획한 행동을 실제 로봇의 움직임으로 실행하는 단계이다.
- 모터와 액추에이터에 명령을 전달하고, 센서 피드백을 통해 목표한 움직임과 실제 움직임의 차이를 확인한다.
- 움직이는 과정에서 장애물이 발생하거나 오차가 생기면 다시 환경을 인지하고 계획을 수정한다.

따라서 로봇의 동작은 단순히 인지 → 계획 → 제어로 끝나는 것이 아니라, **실행 결과를 피드백받아 계속 반복하는 폐루프(Closed-loop) 구조**로 이해할 수 있다.

실제 로봇에서는 잘못된 제어 명령으로 충돌이나 파손이 발생할 수 있으므로, 시뮬레이션 환경에서 알고리즘을 먼저 검증하는 경우가 많다.

### 3. 지능형 로봇과 딥러닝

**[3-1] 규칙 기반 제어와 적응형 행동**

- **규칙 기반 제어(Rule-based Control)**: 특정 상황에서 수행할 동작을 미리 정의하는 방식이다.
- 정해진 환경에서는 안정적으로 동작할 수 있지만, 예상하지 못한 상황에서는 대응하기 어렵다.
- **적응형 행동(Adaptive Behavior)**: 변화하는 환경에 따라 로봇이 행동을 조정하는 방식이다.
- 딥러닝을 활용하면 다양한 데이터를 통해 특징과 행동을 학습하여 새로운 환경에 대응할 수 있다.

실제 환경은 항상 일정하지 않기 때문에 모든 상황에 대한 규칙을 미리 작성하기 어렵다. 이러한 한계를 해결하기 위한 방법 중 하나가 학습 기반 로봇 제어이다.

**[3-2] LLM, VLM, VLA와 Physical AI**

- **LLM(Large Language Model)**: 대규모 텍스트 데이터를 학습하여 언어를 이해하고 생성하는 모델이다.
- **VLM(Vision-Language Model)**: 이미지와 언어 정보를 함께 처리하는 모델로, 시각 정보를 이해하고 언어와 연결할 수 있다.
- **VLA(Vision-Language-Action)**: 이미지와 언어를 입력받아 로봇이 수행할 행동(Action)을 생성하는 모델이다.
- **Physical AI**: 인공지능이 물리적 환경을 인식하고 실제 행동을 수행하도록 하는 기술을 폭넓게 의미한다.

기존의 언어 및 시각 정보 처리에서 나아가, 실제 로봇의 행동까지 연결하는 것이 VLA의 특징이다.

또한 텍스트, 이미지, 오디오 등 서로 다른 형태의 데이터를 함께 학습하는 **멀티모달(Multimodal) 학습**도 지능형 로봇에서 중요한 역할을 한다.

**[3-3] Embodied AI와 Physical AI**

- **Embodied AI**: 물리적 또는 가상적인 몸을 가진 에이전트가 환경과 상호작용하며 지능적인 행동을 수행하는 분야이다.
- **Physical AI**: 실제 물리적 환경에서 AI가 인지, 판단, 행동을 수행한다는 점을 강조하는 개념이다.
- 두 개념은 밀접하게 관련되어 있으며, 로봇과 환경 사이의 상호작용을 중요하게 다룬다.

로봇이 구조화되지 않은 환경에서 작업하려면 소프트웨어의 판단 능력뿐 아니라 센서와 구동 장치를 통한 물리적 상호작용도 필요하다.

### 4. 로보틱스의 응용 분야

**[4-1] SLAM과 3차원 맵핑**

- **SLAM(Simultaneous Localization and Mapping)**: 로봇이 자신의 위치를 추정하면서 동시에 주변 환경의 지도를 생성하는 기술이다.
- 카메라나 LiDAR 등의 센서 정보를 활용해 주변 공간을 파악한다.
- 환경을 표현하는 방법에 따라 2D 또는 3D 지도를 생성할 수 있다.
- 자율주행, 로봇 내비게이션, 자율 탐사 등에 활용된다.
- 최근에는 공간 정보를 신경망 내부에 학습된 형태로 표현하는 Neural Map 관련 연구도 진행되고 있다.

**[4-2] 컴퓨터 그래픽스와 컴퓨터 비전**

- **Computer Graphics**: 3차원 공간의 물체와 장면을 2차원 이미지로 표현하는 기술이다.
- **Computer Vision**: 이미지에서 물체, 공간 구조, 위치 등의 정보를 추정하는 기술이다.
- 그래픽스는 3D 정보를 2D 이미지로 생성하고, 비전에서는 반대로 2D 이미지에서 3D 구조를 추정하기도 한다.
- 두 분야는 카메라 모델, 좌표 변환, 투영 등의 공통 원리를 사용한다.

이러한 기술은 3D Reconstruction, Digital Twin, AR, 로봇 비전 등에 활용된다.

**[4-3] 점검 로봇과 AR 내비게이션**

- 점검 로봇은 사람이 접근하기 어려운 공간에서 주변 환경을 인지하고 이상 상태를 확인하는 데 사용된다.
- 이동 중 장애물을 감지하고, 정상 상태와 현재 상태를 비교하거나 이동 경로를 계획할 수 있다.
- **AR 내비게이션**은 카메라 영상과 위치 추정 기술을 이용해 실제 화면 위에 이동 경로나 방향 정보를 표시하는 방식이다.
- 복잡한 실내 공간에서도 카메라를 활용한 위치 추정과 경로 안내가 가능하다.

### 5. 고수준 판단과 저수준 제어

로봇의 소프트웨어와 하드웨어는 역할에 따라 **고수준(High-level) 판단**과 **저수준(Low-level) 제어**로 나누어 볼 수 있다.

**[5-1] 고수준 판단(High-level)**

- 주변 환경 인지, 경로 계획, 의사결정 등 비교적 복잡한 연산을 담당한다.
- 이미지 처리, SLAM, 경로 탐색, AI 모델 추론 등이 대표적인 작업이다.
- 노트북, SBC, 서버 등 연산 능력이 높은 장치에서 수행한다.
- Linux 및 ROS 2를 이용해 로봇 소프트웨어를 구성하는 경우가 많다.

**[5-2] 저수준 제어(Low-level)**

- 모터, 서보, 센서 등의 하드웨어를 직접 제어한다.
- 고수준 시스템에서 전달된 명령을 바탕으로 액추에이터를 구동하거나 센서 데이터를 읽는다.
- 짧고 일정한 주기로 제어 명령을 처리하는 것이 중요하다.
- 주로 MCU를 이용하며, 펌웨어와 C/C++ 기반의 프로그램으로 구현한다.

**[5-3] 제어 주기(Control Period)**

- **제어 주기**는 제어 알고리즘이 반복적으로 실행되는 시간 간격이다.
- 저수준 제어에서는 일정한 주기를 유지하는 것이 중요하다. 제어 타이밍이 불규칙하면 움직임에 오차가 발생하거나 시스템 안정성이 떨어질 수 있다.
- 일반적인 운영체제에서는 스케줄링에 따라 작업 실행 시간이 달라질 수 있다.
- 실시간 제어가 필요한 시스템에서는 RTOS(Real-Time Operating System)를 사용해 작업의 실행 시간을 관리하기도 한다.

| 구분 | High-level | Low-level |
|---|---|---|
| 역할 | 인지, 계획, 의사결정 | 센서 및 액추에이터 제어 |
| 주요 작업 | SLAM, 경로 계획, AI 추론 | 모터 제어, 센서 입력 처리 |
| 사용 장치 | PC, SBC, 서버 | MCU |
| 소프트웨어 | Linux, ROS 2 등 | 펌웨어, RTOS 등 |
| 중요 요소 | 연산 성능, 알고리즘 | 제어 주기, 응답 시간 |

### 6. SBC와 MCU

**[6-1] SBC(Single Board Computer)**

- 프로세서, 메모리, 입출력 인터페이스 등 컴퓨터의 주요 기능을 하나의 회로 기판에 구성한 장치이다.
- Linux와 같은 운영체제를 실행할 수 있으며, 모니터나 키보드 등의 주변 장치를 연결할 수 있다.
- 일반적으로 MCU보다 복잡한 연산을 처리하기에 적합하다.
- 대표적인 장치로 Raspberry Pi, NVIDIA Jetson 등이 있다.

**[6-2] MCU(Microcontroller Unit)**

- CPU, 메모리, 주변 장치 제어 기능 등을 하나의 칩에 통합한 장치이다.
- SBC에 비해 연산 자원은 제한적이지만 GPIO, ADC, PWM 등을 이용해 하드웨어를 직접 제어하기에 적합하다.
- 모터, LED, 버튼, 센서 등을 제어할 때 사용한다.
- 대표적인 예로 ESP32, Arduino 보드에 사용되는 AVR 계열 MCU 등이 있다.

실제 로봇에서는 SBC가 고수준 판단을 수행하고, MCU가 전달받은 명령에 따라 모터를 제어하는 구조를 사용할 수 있다.

### 7. Linux와 터미널 기초

**[7-1] Linux의 특징**

- **Linux**: 리눅스 커널을 기반으로 하는 운영체제 환경으로, 개발 자유도가 높고 다양한 오픈소스 소프트웨어를 사용할 수 있다.
- 로봇 개발에 많이 사용되는 ROS 2는 Linux, 특히 Ubuntu 환경에서 널리 활용된다.
- 패키지 설치와 관리가 편리하고, 터미널을 이용해 시스템 설정 및 자동화 작업을 수행할 수 있다.

**[7-2] CLI(Command Line Interface)**

- 터미널에 명령어를 입력해 시스템을 조작하는 방식이다.
- GUI와 달리 명령어를 직접 사용하며, 원격 접속이나 반복 작업 자동화 등에 유용하다.

기본적인 Linux 명령어는 다음과 같다.

| 명령어 | 기능 |
|---|---|
| `pwd` | 현재 디렉토리 경로 확인 |
| `cd` | 디렉토리 이동 |
| `ls` | 파일 및 디렉토리 목록 확인 |
| `ls -a` | 숨김 파일까지 확인 |
| `mkdir` | 디렉토리 생성 |
| `touch` | 빈 파일 생성 또는 수정 시간 갱신 |
| `cp` | 파일 및 디렉토리 복사 |
| `mv` | 파일 이동 또는 이름 변경 |
| `rm` | 파일 삭제 |
| `ping` | 대상 장치와의 네트워크 연결 상태 확인 |
| `echo` | 문자열 출력 |

터미널에서 Tab 키를 사용하면 파일명이나 명령어를 자동완성할 수 있다.

**[7-3] 권한과 패키지 관리**

- **`chmod +x`**: 파일에 실행 권한을 추가한다.
- **`sudo`**: 관리자 권한으로 명령어를 실행할 때 사용한다.
- **APT(Advanced Package Tool)**: Ubuntu 등 Debian 기반 Linux에서 사용하는 패키지 관리 도구이다.

```bash
sudo apt update
sudo apt upgrade
```

- `apt update`: 저장소에서 최신 패키지 목록을 가져온다.
- `apt upgrade`: 설치된 패키지를 업데이트한다.

### 8. 로봇 개발 환경

**[8-1] ROS 2와 작업 공간**

로봇 소프트웨어는 센서 처리, 위치 추정, 경로 계획, 제어 등 여러 기능으로 구성된다. ROS 2는 이러한 기능을 서로 연결하고 데이터를 주고받을 수 있도록 지원하는 프레임워크이다.

ROS 2 패키지를 개발할 때는 일반적으로 `colcon` 빌드 도구를 사용하며, 관련 파일을 작업 공간(Workspace)에 구성한다.

실습에서 사용하는 주요 디렉토리는 다음과 같다.

| 디렉토리 | 용도 |
|---|---|
| `colcon_ws` | ROS 2 패키지 개발 및 빌드 |
| `firmware` | MCU 펌웨어 관련 코드 |
| `scratch` | 간단한 테스트 및 임시 코드 |

**[8-2] 개발 도구**

- **VS Code**: Python, C/C++ 등의 코드를 작성하고 수정하는 데 사용하는 코드 편집기이다.
- **Git**: 소스 코드의 변경 이력을 관리하는 분산 버전 관리 시스템이다.
- **GitHub**: Git 리포지토리를 원격으로 저장하고 공유하거나 협업할 수 있는 플랫폼이다.
- **CMake**: 프로젝트의 빌드 과정을 구성하는 도구이다.

이러한 도구를 활용하면 ROS 2 패키지와 MCU 펌웨어를 구분해 개발하고, 소스 코드의 변경 사항을 관리할 수 있다.

### 9. 임베디드 시스템 기초

**[9-1] 임베디드 시스템의 정의**

- **임베디드 시스템(Embedded System)**: 특정 기능을 수행하도록 설계된 컴퓨터 시스템으로, 일반적으로 더 큰 장치나 기계 내부에 포함된다.
- 범용 컴퓨터와 달리 정해진 목적에 맞춰 하드웨어와 소프트웨어가 구성되는 경우가 많다.
- 자동차의 방향지시등, 후진 경고 장치, 가전제품의 제어 장치 등이 대표적인 예시이다.
- 자동차, 산업용 로봇, IoT, 의료기기 등 다양한 분야에서 활용된다.

**[9-2] 전압, 전류, 저항과 GND**

- **전압(Voltage)**: 두 지점 사이의 전위차로, 전류가 흐르게 하는 원인 중 하나이다. 단위는 볼트(V)이다.
- **전류(Current)**: 전하가 이동하는 양으로, 단위는 암페어(A)이다.
- **저항(Resistance)**: 전류의 흐름을 제한하는 성질로, 단위는 옴(Ω)이다.

**옴의 법칙(Ohm's Law)** 은 전압, 전류, 저항의 관계를 나타낸다.

\[
V = IR
\]

- `V`: 전압(Volt)
- `I`: 전류(Ampere)
- `R`: 저항(Ohm)

**GND(Ground)** 는 회로에서 전압을 측정할 때 기준으로 삼는 전위이며, 일반적으로 0V를 기준으로 사용한다.

- **공통 그라운드(Common Ground)**: 서로 연결된 장치들이 같은 전압 기준을 공유하도록 GND를 연결하는 것이다.
- MCU와 센서 또는 액추에이터가 신호를 주고받으려면 공통 기준 전위가 필요한 경우가 많다.
- GND는 전류가 흐르는 방향이 아니라 전압의 기준점이다.

**[9-3] GPIO, 디지털과 아날로그 신호**

- **GPIO(General Purpose Input/Output)**: 입력과 출력 기능을 설정해 사용하는 범용 핀이다.
- **입력(Input)**: 버튼이나 센서 등 외부 장치에서 발생한 신호를 읽는 기능이다.
- **출력(Output)**: LED, 모터 제어 회로 등의 외부 장치에 신호를 전달하는 기능이다.
- **디지털 신호(Digital Signal)**: HIGH와 LOW처럼 구분된 상태로 정보를 표현한다.
- **아날로그 신호(Analog Signal)**: 일정 범위 안에서 연속적으로 변하는 신호이다.
- **로직 전압(Logic Voltage)**: 디지털 회로에서 HIGH와 LOW를 판별하는 전압 기준과 관련된다. ESP32의 GPIO는 일반적으로 3.3V 로직을 사용한다.

**[9-4] ADC(Analog-to-Digital Converter)**

- ADC는 아날로그 입력 전압을 디지털 값으로 변환하는 장치이다.
- 센서에서 측정한 연속적인 전압을 MCU가 처리할 수 있는 정수 값으로 변환할 때 사용한다.
- ADC의 해상도가 높을수록 같은 입력 범위를 더 세밀한 단계로 구분할 수 있다.

ADC의 해상도가 n비트일 때 디지털 값의 범위는 다음과 같다.

\[
0 \sim (2^n - 1)
\]

| ADC 해상도 | 디지털 값 범위 |
|---|---|
| 8비트 | 0 ~ 255 |
| 10비트 | 0 ~ 1023 |
| 12비트 | 0 ~ 4095 |

- **비트(bit)**: 0 또는 1을 나타내는 가장 작은 정보 단위이다.
- **바이트(byte)**: 일반적으로 8비트로 구성된다.

ESP32에서는 ADC를 이용해 가변저항이나 센서의 아날로그 전압을 읽을 수 있다. 이후 실습에서는 GPIO를 이용한 LED·버튼 제어와 ADC를 통한 센서 입력 처리를 직접 다룬다.

## 임베디드 기초 실습: ESP32 핀 구조와 디지털·아날로그 입출력

앞서 학습한 전압, 전류, GND, GPIO, ADC 개념을 바탕으로 ESP32의 핀 구조를 살펴보고, LED·버튼·가변저항을 연결해 입출력을 제어하는 실습을 진행했다.

이번 실습에서는 `pinMode()`, `digitalWrite()`, `digitalRead()`, `analogRead()` 등의 함수를 사용하고, PWM을 통한 LED 밝기 조절과 시리얼 통신으로 센서 값을 확인하는 방법을 다뤘다.

### 10. 임베디드 기초 용어와 전기 개념

**[10-1] VCC, 전압, 전류, 저항**

- **VCC**: 회로에 전원을 공급하는 단자로, 사용하는 장치에 맞는 전압을 연결해야 한다.
- **전압(Voltage)**: 전류를 흐르게 하는 전위차로, 물이 흐르도록 만드는 압력에 비유할 수 있다.
- **전류(Current)**: 전하가 흐르는 양이다. 전기 회로에서는 전압과 전류를 함께 고려해야 하며, 허용 범위를 초과하면 부품이 손상될 수 있다.
- **과전류(Overcurrent)**: 회로에 허용된 수준 이상의 전류가 흐르는 현상으로, 발열이나 부품 고장의 원인이 된다.
- **저항(Resistance)**: 전류의 흐름을 제한하는 역할을 한다. LED를 연결할 때 과도한 전류가 흐르지 않도록 저항을 직렬로 연결하며, 실습에서는 약 220Ω의 저항을 사용했다.

**[10-2] 디지털과 아날로그 신호**

- **디지털 신호**: HIGH와 LOW 두 상태로 구분되는 신호로, LED를 켜거나 끄고 버튼 입력을 확인할 때 사용한다.
- **아날로그 신호**: 일정 범위에서 연속적으로 변하는 신호로, 가변저항이나 일부 센서의 출력이 이에 해당한다.
- **ADC(Analog-to-Digital Converter)**: 아날로그 전압을 디지털 값으로 변환하는 장치이다. 변환된 값의 범위는 ADC 해상도에 따라 달라진다.

### 11. ESP32 핀 구조

**[11-1] 전원 핀(5V, 3V3, VIN, GND)**

- **GND**: 회로의 기준 전위(0V)로 사용하는 핀이다. 서로 연결된 장치는 공통 GND를 사용해야 신호를 안정적으로 주고받을 수 있다.
- **5V**: 보드에 따라 USB 또는 외부 전원에서 공급되는 5V 전원과 연결되는 핀이다.
- **3V3**: ESP32와 3.3V 주변 장치에 사용하는 전원 핀이다.
- **VIN**: 외부 전원을 보드에 공급하기 위한 핀이며, 허용 입력 전압은 보드 모델에 따라 다르므로 핀 배치도와 사양을 확인해야 한다.

ESP32의 GPIO 신호 전압은 일반적으로 3.3V 기준이므로, 5V 신호를 GPIO에 직접 입력하지 않도록 주의해야 한다.

**[11-2] 디지털 핀과 아날로그 핀**

- **GPIO(General Purpose Input/Output)**: 입력 또는 출력으로 설정해 사용하는 범용 핀이다. 핀마다 사용할 수 있는 기능에 차이가 있다.
- **디지털 핀**: `digitalRead()`로 HIGH/LOW 상태를 읽거나 `digitalWrite()`로 출력 신호를 제어한다.
- **아날로그 입력 핀**: ADC 기능이 지원되는 핀에서 아날로그 전압을 읽을 수 있다.
- **PWM 출력**: ESP32는 PWM 기능을 지원하며, 출력이 가능한 여러 GPIO에 PWM 신호를 할당할 수 있다. 일반 아두이노 보드와 달리 물결(~) 표시가 있는 핀만 사용할 수 있는 것은 아니다.

핀 번호와 사용 가능한 기능은 보드마다 다를 수 있으므로 실제 회로를 구성할 때 핀 배치도를 확인해야 한다.

### 12. 레지스터와 저수준 동작

**[12-1] 데이터 방향 레지스터와 출력 레지스터**

마이크로컨트롤러는 내부 레지스터를 이용해 GPIO의 입력·출력 상태와 주변 장치의 동작을 제어한다.

- **데이터 방향 레지스터**: 핀을 입력으로 사용할지 출력으로 사용할지 설정하는 데 관여한다. AVR 계열에서는 DDR(Data Direction Register)이라는 명칭을 사용한다.
- **출력 레지스터**: 출력 핀의 HIGH/LOW 상태를 설정하는 데 사용한다.
- **ADC 관련 레지스터**: ADC의 설정과 변환 결과를 관리한다. ADC 해상도에 따라 표현할 수 있는 디지털 값의 범위가 달라진다.

ESP32는 AVR 계열 아두이노와 내부 레지스터 구조가 다르지만, 레지스터를 통해 하드웨어를 제어한다는 기본 원리는 같다.

**[12-2] 고수준 언어와 저수준 동작**

- 아두이노에서는 `pinMode()`, `digitalWrite()` 같은 함수를 통해 GPIO를 쉽게 제어할 수 있다.
- 실제 하드웨어에서는 이러한 함수의 동작이 드라이버와 레지스터 설정을 통해 처리된다.
- 레지스터의 역할을 이해하면 코드가 하드웨어에서 어떻게 동작하는지 파악할 수 있다.

### 13. LED 제어 실습

**[13-1] 핀 모드 설정과 디지털 쓰기**

LED를 제어하려면 사용할 GPIO를 출력 모드로 설정하고 HIGH 또는 LOW 신호를 보내면 된다.

- **상수 정의**: LED가 연결된 핀 번호를 코드 상단에 정의하면 핀 번호를 변경하거나 코드를 관리하기 편하다.
- **`setup()`**: 프로그램이 시작될 때 한 번 실행되며, 핀 모드나 시리얼 통신 등을 초기화한다.
- **`loop()`**: `setup()` 실행 이후 반복적으로 호출되는 함수이다.
- **`pinMode(pin, OUTPUT)`**: 지정한 핀을 출력 모드로 설정한다.
- **`digitalWrite(pin, HIGH)`**: 지정한 핀에 HIGH 신호를 출력한다.
- **`digitalWrite(pin, LOW)`**: 지정한 핀에 LOW 신호를 출력한다.

LED를 저항과 함께 연결한 뒤 출력 상태를 변경해 점등과 소등을 제어한다. LED의 연결 방향에 따라 HIGH 또는 LOW에서 켜지는 상태는 달라질 수 있다.

### 14. 버튼 입력 실습

**[14-1] 풀다운 저항과 플로팅 전압**

버튼은 눌렀을 때와 누르지 않았을 때 서로 다른 디지털 신호가 입력되도록 회로를 구성한다.

- **플로팅(Floating)**: 입력 핀이 HIGH나 LOW 중 어느 쪽에도 안정적으로 연결되지 않은 상태이다. 외부 잡음의 영향으로 입력값이 불규칙하게 바뀔 수 있다.
- **풀다운 저항(Pull-down Resistor)**: 버튼을 누르지 않았을 때 입력 핀을 GND와 연결해 기본 상태를 LOW로 유지한다.
- **풀업 저항(Pull-up Resistor)**: 입력 핀을 전원 전압 쪽으로 연결해 기본 상태를 HIGH로 유지한다.

| 구분 | 버튼을 누르지 않았을 때 | 버튼을 눌렀을 때 |
|---|---|---|
| 풀다운 방식 | LOW | HIGH |
| 풀업 방식 | HIGH | LOW |

위 표는 풀다운 방식에서 버튼을 전원에 연결하고, 풀업 방식에서는 버튼을 GND에 연결한 일반적인 회로를 기준으로 한다.

ESP32는 내부 풀업·풀다운 기능도 지원하며, `INPUT_PULLUP`, `INPUT_PULLDOWN` 등의 설정을 활용할 수 있다.

**[14-2] 버튼 바운싱과 디바운싱**

- **바운싱(Bouncing)**: 버튼의 기계적 접점이 붙거나 떨어지는 순간 접촉 상태가 짧은 시간 동안 여러 번 바뀌는 현상이다.
- 버튼을 한 번 눌러도 HIGH와 LOW가 여러 번 반복되어 입력된 것처럼 인식될 수 있다.
- **디바운싱(Debouncing)**: 바운싱으로 발생하는 불필요한 입력 변화를 걸러내는 처리 방식이다.
- 입력 상태가 일정 시간 유지되었을 때만 실제 버튼 입력으로 인정하는 방법 등을 사용할 수 있다.

**[14-3] 시리얼 통신(Serial Communication)**

버튼이나 센서의 입력값을 확인하기 위해 시리얼 모니터를 사용한다.

- **시리얼 통신**: 데이터를 비트 단위로 순서대로 전송하는 직렬 통신 방식이다.
- **보드레이트(Baud Rate)**: 초당 전송되는 신호 상태 변화의 횟수를 나타낸다. 일반적인 UART 설정에서는 비트 전송 속도와 같은 수치로 사용하며, 9600과 115200 등이 많이 쓰인다.
- **`Serial.begin(115200)`**: 시리얼 통신을 115200 baud로 시작한다.
- **`Serial.print()`**: 값을 출력하고 줄바꿈하지 않는다.
- **`Serial.println()`**: 값을 출력한 뒤 줄바꿈한다.

시리얼 모니터의 통신 속도를 코드와 동일하게 설정해야 출력값을 정상적으로 확인할 수 있다.

### 15. 가변저항과 ADC 실습

**[15-1] 가변저항의 원리와 아날로그 읽기**

- **가변저항(Potentiometer)**: 회전축을 돌려 저항의 비율을 변경할 수 있는 부품이다.
- 가변저항의 양 끝을 전원과 GND에 연결하면 가운데 단자에서 회전 위치에 따라 달라지는 전압을 얻을 수 있다.
- ESP32는 이 전압을 ADC로 측정하고 디지털 값으로 변환한다.
- **`analogRead(pin)`**: 지정된 아날로그 입력 핀의 전압을 읽어 정수로 반환한다.

ADC 해상도가 n비트일 때 표현할 수 있는 디지털 값의 범위는 `0 ~ (2^n - 1)`이다.

| ADC 해상도 | 디지털 값 범위 |
|---|---|
| 8비트 | 0 ~ 255 |
| 10비트 | 0 ~ 1023 |
| 12비트 | 0 ~ 4095 |

ESP32의 기본 `analogRead()` 해상도는 일반적으로 12비트이므로 0~4095 범위의 값을 반환한다. 설정에 따라 해상도를 변경할 수 있다.

**[15-2] PWM과 듀티 사이클**

- **PWM(Pulse Width Modulation)**: 디지털 출력을 빠르게 켜고 끄면서 HIGH 상태의 시간 비율을 변경하는 방식이다.
- **듀티 사이클(Duty Cycle)**: PWM 한 주기에서 HIGH 상태가 차지하는 시간의 비율이다.
- 듀티 사이클이 0%이면 항상 LOW이고, 100%이면 항상 HIGH이다.
- LED에 PWM을 적용하면 듀티 사이클에 따라 평균 전류가 달라져 밝기를 조절할 수 있다.

예를 들어 듀티 사이클이 50%라면 한 주기의 절반 동안 HIGH를 출력한다. 이는 평균 전압이 전원 전압의 약 절반이 된다는 뜻이며, LED의 실제 밝기가 정확히 절반이라는 의미는 아니다.

ESP32에서 아두이노의 `analogWrite()`를 사용하는 경우 기본 해상도는 8비트로, 0~255 범위를 통해 PWM 출력을 제어할 수 있다. 해상도 설정은 변경할 수 있다.

PWM은 디지털 신호의 시간 비율을 조절하는 방식이며, 실제 연속적인 아날로그 전압을 출력하는 DAC와는 다르다. 일반 ESP32에는 GPIO25와 GPIO26에 연결된 8비트 DAC도 내장되어 있다.

**[15-3] map 함수를 이용한 값 변환**

ADC로 읽은 값을 PWM 출력에 사용하려면 입력 범위를 출력 범위에 맞게 변환해야 한다.

- **매핑(Mapping)**: 입력값을 다른 수치 범위로 비례 변환하는 과정이다.
- 아두이노에서는 `map()` 함수를 사용해 입력값의 최솟값·최댓값과 출력값의 최솟값·최댓값을 지정할 수 있다.
- 예를 들어 10비트 ADC 값인 0~1023을 8비트 PWM 범위인 0~255로 변환할 수 있다.
- ESP32의 기본 12비트 ADC를 사용한다면 입력 범위를 0~4095로 설정해야 한다.

```cpp
int adc_value = analogRead(pot_pin);
int pwm_value = map(adc_value, 0, 4095, 0, 255);
analogWrite(led_pin, pwm_value);
```

이 코드는 가변저항의 위치에 따라 LED 밝기가 바뀌도록 하는 기본적인 예시이다. `pot_pin`과 `led_pin`은 실제 연결한 핀 번호로 미리 정의해야 한다.

### 16. 개발 환경 구성

**[16-1] 리눅스 아두이노 IDE 설치와 커스텀 명령어**

- **`/opt` 디렉토리**: 추가 소프트웨어를 설치할 때 자주 사용하는 경로이다.
- **`sudo`**: 관리자 권한이 필요한 설치 및 시스템 설정 작업에 사용한다.
- **`chmod +x`**: 파일에 실행 권한을 추가하는 명령어이다.
- **쉬뱅(Shebang)**: 스크립트 첫 줄에 `#!/bin/sh`와 같이 작성하며, 스크립트를 실행할 인터프리터를 지정한다.
- 자주 사용하는 실행 스크립트는 시스템의 명령어 검색 경로에 심볼릭 링크로 등록하면 다른 디렉토리에서도 명령어처럼 실행할 수 있다.

**[16-2] 시리얼 포트 권한 설정**

- ESP32를 USB로 연결하면 리눅스에서는 `/dev/ttyUSB0`, `/dev/ttyACM0` 등의 장치 파일로 인식될 수 있다.
- 일반 사용자에게 시리얼 포트 접근 권한이 없으면 IDE에서 보드를 연결하거나 코드를 업로드할 때 오류가 발생할 수 있다.
- Ubuntu에서는 일반적으로 사용자를 `dialout` 그룹에 추가해 접근 권한을 설정한다.

```bash
sudo usermod -aG dialout $USER
```

그룹 변경 사항은 로그아웃 후 다시 로그인하면 적용된다. 필요한 경우 재부팅해 적용할 수도 있다.

### 17. PCB 키트 구성품

**[17-1] IMU(관성 측정 장치)**

- **IMU(Inertial Measurement Unit)**: 로봇의 움직임과 자세를 추정하는 데 사용하는 센서이다.
- **가속도계(Accelerometer)**: X, Y, Z축 방향의 가속도를 측정하며, 중력 성분도 포함된다.
- **자이로스코프(Gyroscope)**: X, Y, Z축을 기준으로 한 회전 각속도를 측정한다.
- **지자기 센서(Magnetometer)**: 지구 자기장을 측정해 방향을 추정하는 데 사용한다. 주변 금속이나 자성 물체로 인해 실내에서는 측정 오차가 발생할 수 있다.

IMU 구성에 따라 가속도계와 자이로스코프만 포함하거나 지자기 센서까지 함께 사용할 수 있다.

**[17-2] 서보 모터**

- **서보 모터(Servo Motor)**: 목표 위치나 각도를 지정해 제어할 수 있는 모터이다.
- 실습용 서보 모터는 일반적으로 약 0~180도 범위에서 동작하지만, 실제 회전 범위는 제품마다 다르다.
- 제어 신호의 펄스 폭을 변경해 목표 각도를 지정한다. 일반적인 RC 서보 모터는 약 50Hz 주기의 제어 신호를 사용한다.
- 실습에서 사용하는 서보 모터의 배선은 갈색(GND), 빨간색(VCC), 노란색(신호선)으로 구분된다.

모터를 연결하기 전에는 정격 전압과 전류를 확인해야 하며, 소비 전류가 큰 모터는 별도 전원을 사용하는 것이 필요할 수 있다.

**[17-3] 라이다와 버저**

- **라이다(LiDAR, Light Detection and Ranging)**: 레이저를 이용해 주변 물체까지의 거리를 측정하는 센서이다.
- 회전형 2D 라이다는 주변을 스캔해 거리 정보를 수집하며, 제품에 따라 360도 스캔이 가능하다.
- 로봇에서는 장애물 감지, 위치 추정, 지도 작성 등에 활용한다.
- **버저(Buzzer)**: 전기적 신호를 소리로 변환하는 장치로, 알림음이나 경고음 출력에 사용한다.
- 실습에서는 버저를 5번 핀에 연결하며, 사용하는 버저 종류에 따라 출력 신호나 주파수를 조절할 수 있다.

### 실습 정리

이번 실습에서는 ESP32의 GPIO를 직접 사용하면서 디지털 출력, 디지털 입력, 아날로그 입력의 차이를 확인했다.

LED는 `digitalWrite()`로 켜고 끌 수 있고, 버튼은 `digitalRead()`를 통해 상태를 확인할 수 있다. 버튼 입력에서는 풀업·풀다운 저항이 필요한 이유와 바운싱 문제도 살펴봤다.

가변저항 실습에서는 `analogRead()`로 측정한 ADC 값을 `map()`으로 변환하고, PWM 출력에 적용해 LED 밝기를 조절하는 과정을 학습했다.

이를 통해 센서에서 입력을 받고, 입력값을 처리한 뒤, 액추에이터를 제어하는 임베디드 시스템의 기본 동작 구조를 이해할 수 있었다.
